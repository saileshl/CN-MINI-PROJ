VERCEL DEPLOYMENT REQUIREMENT
==================================================

The FRONTEND must be fully deployable to Vercel.

The project must not merely be "compatible with Vercel."

It must actually be configured and tested for a production Vercel deployment.

Requirements:

- Next.js production build must succeed.
- No localhost URLs hardcoded into production frontend code.
- No development-only dependencies required at runtime.
- Production environment variables must be documented.
- Create .env.example with every required variable.
- Use environment variables for backend URLs and configuration.
- Configure CORS correctly.
- Configure WebSocket/backend URLs correctly.
- Make sure browser-side code uses the correct production backend URL.
- Make sure refresh/navigation works correctly on Vercel.
- Avoid filesystem-dependent functionality in Vercel serverless functions.
- Do not rely on a local development server being available after deployment.

If a persistent WebSocket backend cannot technically be hosted by Vercel,
DO NOT attempt to fake persistent WebSocket behavior using Vercel serverless
functions.

Instead:

FRONTEND:
Vercel

BACKEND / WEBSOCKET GATEWAY:
A suitable persistent backend host

PYTHON AGENT:
User's local computer

Document this architecture clearly.

The final project must include deployment instructions for both the
Vercel frontend and the persistent backend.
